# LAN and ED2 UART diagnosis

The dashboard LAN indicator previously reflected only the sonar socket. It now uses an explicit LAN witness, an open passive UART TCP connection, an established sonar TCP session/recent UDP data, or live decoded camera video. An unconfigured/unconfirmed network shows `?`, not a claim that the switch is powered off. The tooltip and Settings > Integrations explain the evidence. Local interface/link/IP/mask information is shown separately and never proves the Ethernet link on the far side of GR01.

An unmanaged switch cannot report its power/link state to G20 through an ordinary radio telemetry heartbeat. Set the actual ED2 private IPv4 address and its web service port (normally 80, verify the device configuration). Enable LAN verification. A TCP handshake is checked every five seconds with a 1.5 second timeout and a maximum 12-second witness lifetime. No HTTP or serial payload is sent. A successful configured remote witness indicates network reachability; it does not measure switch power or prove UART traffic. No factory IP or GR01 subnet is assumed. No IP scan is run automatically.

For UART, set the actual ED2 UART network port and configure ED2 as TCP Server with UART settings matching its connected device. Press Listen UART. NAVO opens a TCP client, displays an RX counter and the most recent 1024 bytes in HEX/printable text, and sends no serial commands. TCP connected with no data remains UART unconfirmed. Received bytes do not by themselves verify baud/protocol correctness. A UART with no transmitting source cannot be verified by passive listening alone.

The passive serial test is manual only, has no automatic reconnection, releases its port when hidden/collapsed/closed, and stops during replay. LAN witness configuration persists; preview data and UART sessions do not. The web witness port must differ from UART; ports already used by known active sonar/camera/MAVLink endpoints are excluded, and a newly occupied UART endpoint closes the diagnostic listener. Other apps cannot be enumerated: close USR tools/FLY/other clients yourself when testing single-client converters. No real boat hardware has been tested by the agent.

Tests: native Qt TCP loopback tests cover handshake, passive receive, zero transmitted bytes, bounded preview, active-port exclusion, replay, endpoint reset and invalid targets. UI tests use production QML at 320/480/800 px and test expanded/collapsed state, invalid ports, RX view, stop and replay controls. Existing Ethernet settings and settings routing tests are retained. Native checks run in core CI; no Android build is automatically added for this stacked PR.
